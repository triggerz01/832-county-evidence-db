## 2. 建议的测试顺序（约 20 分钟）

### 路线 A · 公众视角（3 分钟）——先看"这库有什么用"

1. **不登录**直接访问 `/cases`：只看到 `TC-006`、`TC-007` 两条已发布案例。这就是"对外发布的成果"。
2. 访问 `/reports`（资料检索）：搜 `涞水`、再按省份筛选。注意"已整理案例"列——
   显示的 `n 个` 是链接，`未整理` 是灰字。底部提示：295 篇报道还没整理成案例，这是**工作量缺口**，不是覆盖率。
3. 访问 `/stats`（统计核验）：五块内容，每块都是一条真 SQL。
   - 各省报道篇数（`GROUP BY`）
   - 同时采用就业 + 土地流转的案例（`HAVING COUNT(DISTINCT 方式)=2`）→ 只有 `C-003` 一条
   - 涞水 2024 计划资金按类别汇总（`JOIN + SUM`）→ 合计 **19518.386018 万元**
   - 金额勾稽（`HAVING ABS(差)>ε`）→ **0 处不一致**（43 个项目 vs 158 条实施地点行）
   - 缺口与逾期

**看点**：这里所有数字都来自 SQLite 实库，不是写死的。

---

### 路线 B · 案例全生命周期（8 分钟）★核心，务必走一遍

用 `TC-001`（队员甲，草稿）或自己新建一条。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 登录**队员甲** → `/cases/new` → 填县域、产业、标题、说法摘要、勾一个帮扶方式、**必须勾至少一条出处摘录** → 保存 | 状态 `草稿`，只有自己能看到 |
| 2 | 打开该案例 → 点「提交审核」 | 状态 `待审核`，同时"修改/删除"按钮消失 |
| 3 | 退出，登录**审核员** → 打开这条 → 点「退回」但**理由留空** | 页面顶部红字提示"退回必须写明理由"，状态不变 |
| 4 | 填理由（例如"出处只挂了标题，没有具体段落位置"）→ 退回 | 状态 `退回补正` |
| 5 | 退出，登录**队员甲** → 打开 → 状态是退回补正，可以「修改」→ 改完再「提交审核」 | 回到 `待审核` |
| 6 | 登录**审核员** → 「通过」 | 状态 `已审核` |
| 7 | 登录**队长** → 打开 → 出现「发布」按钮 → 点 | 状态 `已发布` |
| 8 | **退出登录**（不登录）→ 打开 `/cases` | 这条能看到了；点进去只有内容，没有任何操作按钮 |

**额外验一条硬规则**：新建案例时**什么出处都不勾**，保存后直接点「提交审核」——
应该被拦下，红字提示"这条案例还没挂任何出处摘录，不能提交审核"，状态仍是 `草稿`。
这是这条流水线存在的理由：没有能追到原文的说法，进不了对外口径。

**看点在案例详情页底部**：「操作记录」表把每一次新建、提交、退回、通过、发布
连人带时间都记下来了——这就是审计日志（`audit_log`），和业务表在同一个事务里写。

### 路线 C · 任务流水线 + 版本追溯（8 分钟）★第二个核心

用 `TT-004`（霍邱县 / 队员乙 / 退回补正 / 截止 2026-11-10，已逾期）。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 登录**队员乙** → `/tasks` → 打开 `TT-004` | 状态 `退回补正`，能看到「提交版本」表单（标题 + 版本说明**都必填**） |
| 2 | 提交一份材料 | 版本号自动 +1，状态 → `待审核` |
| 3 | 登录**审核员** → 打开 → 「退回」+ 写理由 | `退回补正`，审核记录里多一行 |
| 4 | 登录**队员乙** → 再提交一份 | 变成**第 2 版**（或 3 版），状态 → `待审核` |
| 5 | 登录**审核员** → 「通过」 | `已完成` |
| 6 | 登录**队长** → 「发布」 | `已发布` |

**关键观察**：`/tasks/TT-004` 的「提交版本」表里，每次提交都是**新增一行**，
旧版本永远不被覆盖，版本号递增。这是"调研队台账"真正值钱的地方——能回答
"第 2 版是谁什么时候交的、为什么被退回"。

**再去看总览页** `/` 的「逾期未交指定材料」：`TT-004` 在上面（截止日已过且没有
按期提交的对应材料）。你提交材料后它应该从这张表里消失。
判定用的是 `NOT EXISTS` 子查询，不是看状态字段——状态是"人标的"，材料是"事实"。

### 路线 D · 权限确实是"被拦住"，不是"藏起来"（2 分钟）

改地址栏，手动输 URL，看会不会被挡：

| 操作 | 预期 |
|---|---|
| 队员甲 访问 `/cases/TC-002`（队员乙的草稿） | **404**（不是 403——故意不告诉他"这条存在但你没权限"） |
| 队员甲 访问 `/cases/TC-004`（队员乙的退回稿） | 404 |
| 队员甲 访问 `/tasks/TT-002`（派给队员乙） | 404 |
| 队员乙 访问 `/cases/TC-003`（队员甲的待审稿） | 404 |
| 审核员 访问 `/cases/TC-003` | 200，并且看到「通过 / 退回」按钮 |
| 队员甲 打开自己的 `TC-003` | 200，但**没有**审核按钮（不能自审） |
| 队员甲 直接 POST `/cases/TC-001/publish` | 403 |

**看点**：权限不是在 Python 里 `if` 完筛一遍，而是 `case_scope()` / `task_scope()`
生成 WHERE 条件拼进 SQL，**在数据库层就把不可见的行筛掉了**。

### 路线 E · 让数据库自己拦（1 分钟）——最能体现"概论考点"

这些是**约束和触发器**在挡，不是代码在挡。可以在 `sqlite3` 命令行里直接试：

```bash
cd E:/832-statistc
sqlite3 832_test_playground.sqlite
```

```sql
-- 1) 退回必须写理由（表级 CHECK）
INSERT INTO review_action(version_id,reviewer_id,decision,reason,acted_at)
VALUES (1,5,'退回','   ','2026-11-20 10:00');
-- 预期：CHECK constraint failed

-- 2) 同一个人不能既是提交人又是审核人（触发器 RAISE(ABORT)）
--    先查出版本 1 的提交人，再用同一人审核
INSERT INTO review_action(version_id,reviewer_id,decision,reason,acted_at)
SELECT version_id, submitted_by, '通过', '自审', '2026-11-20 10:00'
  FROM deliverable_version WHERE version_id = 1;
-- 预期：submitter cannot review own version

-- 3) 一个任务只能有一个负责人（部分唯一索引 idx_one_task_lead）
INSERT INTO task_assignment(task_id,user_id,is_lead) VALUES ('TT-001',4,1);
-- 预期：UNIQUE constraint failed

-- 4) 同一篇报道里同一人物不能重复登记（idx_mention_unique）
INSERT INTO person_mention(report_id,person_name,role_text,context_summary)
SELECT report_id, person_name, role_text, '重复' FROM person_mention LIMIT 1;
-- 预期：UNIQUE constraint failed

-- 5) 删掉还有外键引用的县（RESTRICT）
DELETE FROM county WHERE county_id = (SELECT county_id FROM industry_case LIMIT 1);
-- 预期：FOREIGN KEY constraint failed

.quit
```

> 想验证完整性没坏：`PRAGMA foreign_key_check;` 返回空 = 无违规。

## 5. 现在还测不了的部分（已知边界，别当成 bug）

| 现象 | 原因 |
|---|---|
| `/reports` 只能按**标题**和**县域**搜，搜正文搜不到 | 采集的 JSON 里只有标题/URL/县/省/日期，**报道正文没入库**。要做全文检索得先 jieba 预分词再建 FTS5 虚拟表 |
| 提交材料只能填"标题 + 说明"，传不了文件 | 没做文件上传，`source_document` 只登记元数据 |
| 结果最多 200 条，没有翻页 | 样本库规模小，故意省掉分页 |
| 表单没有 CSRF token | 本地演示，交作业前如果要放到公网需要补 |
| 案例不能"归档/隐藏" | 状态机只有 5 个状态，够用就没加 |
