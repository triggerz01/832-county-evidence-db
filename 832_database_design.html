统计边界“县域特色产业年度产值”是产业背景数据。它不等于某个村、企业或帮扶案例带来的产值，也不能单凭产值证明农户增收。案例受益人数、分红和工资等，应依据原文另存为受益记录。

从人大“832工程”公开调研报道中，把一个基地、一种经营模式整理为一条案例。点击案例可查看具体做法、帮扶方式和原文；同县同产业指标只显示为背景。

每一行表示“某篇来源文献对某县某产业某年度指标的一次公开表述”。同县、同年、同指标的不同来源允许并存；点“详情”查看原文口径。

核验流程

从原文到可检索记录

1登记文献

保存网址、标题、发布机构、发布日期；网址唯一，避免重复录入。

2抽取记录

报道拆为具体案例；数值拆为一条条年度指标，保留原文措辞。

3核查口径

核对县或乡镇范围、统计年、是否实绩，以及“一产”“综合”等定义。

4发布检索

已审核内容供公众查看；冲突值并列保留并显示核验状态。

必须能解释的表间关系

公开报道 1 → N 帮扶案例一篇调研报道写多个基地。
案例 N ↔ M 帮扶方式霍邱莲藕案例同时涉及土地流转和就业。
来源文献 1 → N 指标记录一份年度总结含多个产业指标。
县域＋产业 → N 年度指标同一年允许不同来源说法并存。
系统用户 1 → N 审核记录记录是谁、何时、对哪条数据作出决定。

约束与范式取舍

PK
实体独立主键行政代码、网页网址另设唯一约束；桥表使用复合主键。
FK
外键保证引用完整删除来源前先检查案例证据和指标引用；审核记录建议保留。
3N
按第三范式拆分县名、产业名、来源标题只在各自主表保存，避免更新不一致。
!
冲突记录不能被唯一约束抹掉一条指标记录代表一个来源说法，不能只用“县＋产业＋年份”做唯一键。

这份 HTML 展示要做的系统。正式大作业还须实现真实关系数据库和后端查询；所有统计、筛选、审核记录最终应落到数据库中执行。

实现路线

从静态原型到可运行数据库系统

01 / 存储
PostgreSQL 或 SQLite执行 DDL、PK/FK/UNIQUE/CHECK 约束；保存案例、指标、来源及审核记录。
02 / 服务
Python 后端 API实现登录角色、录入、更新、审核和 SQL 查询；统计由数据库执行。
03 / 界面
动态网页把本原型中的筛选、详情、核验台接到后端接口，展示数据库结果。
