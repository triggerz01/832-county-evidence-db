业务规则

每次状态变化都有前置条件

指派

县域必须存在，负责人必须属于任务队伍；同县可有不同主题任务。创建者和时间写审计日志。

提交

队员只提交本人任务。材料有类型、标题、链接或附件、引用证据；退回重交不覆盖旧版本。

审核与发布

审核员不能审核本人提交。退回必填理由；通过后由队长发布。公众只读已发布成果。

案例是从公开报道或政府表中提取的结构化记录，不等于原始访谈。下面既有已核对的真实案例，也有可新建的演示草稿；原文一直保留单独的来源网址。

数据管理

案例的查询、插入、更新与删除

已发布真实样本不可直接改写；本人草稿可编辑或软删除，退回补正可编辑重交。

新建案例草稿

新建草稿会标为“课程演示”；正式系统还须登记来源机构、发表日期、段落/表格行号，并让同一来源网址在 source_document 中只存一次；一篇报道可供多个案例引用。

审核是实际的数据状态流转：队员提交的日志、新闻或案例报告进入待审核队列；审核员可以通过，或填写理由退回。页面仅演示权限逻辑，正式系统必须在每个 API 和数据库事务中校验。

作业第 5 页要求
逐功能输入、前置条件与输出
创建任务
POST /tasks 输入县域、主题、队员、截止日；仅队长/管理员，县与队员须存在。事务写 field_task 与 task_assignment，输出任务号。
提交资料
POST /deliverables 输入任务、类型、标题、链接/附件；仅被指派队员，任务须开放。写新版本，输出“待审核”。
审核与退回
POST /reviews 输入版本、决定、意见；审核员且非提交人，退回必填理由。写不可覆盖流水，更新任务状态。
案例 CRUD
POST/PATCH/DELETE /cases 草稿由本人维护，删除为软删除；发布版改动生成新版本。输出案例与操作日志。
项目与证据详情
GET /projects 输入县域、类别、项目名与页码；输出项目、原始两套编号、实施地点行、来源链接及口径说明。跨来源匹配须人工确认。
组合检索
GET /search 输入县域、人物、产业、方式、状态、关键词；按权限过滤未发布资料，输出分页结果与原文链接。
统计分析
GET /analytics 内部任务统计限授权角色；公开项目汇总可对外展示。后端执行参数化 JOIN、GROUP BY、NOT EXISTS 查询，返回图表与来源明细。

      
实现边界这份 HTML 是可操作的设计原型，浏览器中的新增、审核与发布仍保存在本地，尚未接入已生成的 SQLite 样本库。完整课程成品还需后端 API、登录鉴权、教材式 E-R 图、运行说明及截图。
